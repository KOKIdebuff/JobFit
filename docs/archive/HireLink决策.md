## 1. 用户系统
- **功能目标**：解决求职者、HR 两类身份的登录、注册、权限隔离和页面访问控制。
- **输入与输出**
  - **输入**：手机号/邮箱、密码、角色、企业信息。
  - **输出**：登录 Token、用户资料、角色权限、可访问菜单。
- **子技术决策点**
  - 前端：登录页、注册页、角色路由守卫。
  - 后端：JWT 鉴权、RBAC 权限校验。
  - 数据库：`users`、`companies`、`roles`。
  - 第三方：可用 Supabase Auth。
  - 异步：不必要。
  - 实时通信：不需要。
- **方案选择**：平衡级方案选择 FastAPI 自建 JWT + RBAC，可控、可迁移、适合自建。因为 HR 数据隔离和企业租户权限会越来越重要。
- **可落地性说明**：比赛中只要实现两种角色登录后进入不同首页即可，后台维护可以先用脚本完成。
- **风险与注意事项**：权限隔离不能只靠前端判断，后端接口必须校验企业归属。密码、Token、企业数据都不能明文暴露。

## 2. 简历上传与解析
- **功能目标**：把 PDF/Word 简历转成结构化数据，供画像、匹配、面试题生成使用。
- **输入与输出**
  - **输入**：PDF/DOCX 简历文件、用户 ID。
  - **输出**：教育背景、项目经历、实习经历、技能标签、原文文本、结构化 JSON。
- **子技术决策点**
  - 前端：上传组件、解析状态展示。
  - 后端：文件接收、文本抽取、LLM 结构化。
  - 数据库：简历元数据、解析结果。
  - 文件存储：需要。
  - 大模型：建议需要。
  - 异步任务：建议需要，MVP 可后台任务。
  - 向量库：MVP 不需要。
- **方案对比**
  - MVP：`pdfplumber` / `pypdf` / `python-docx` + LLM JSON 提取，快、展示效果好，格式复杂时不稳定，适合比赛原型。
  - 平衡级：文本抽取 + OCR 兜底 + LLM 校验 + 人工修正界面，准确率更高，但成本和开发量增加，适合真实试点。
- **最终选择**：MVP 用开源解析库提取文本，再让 LLM 输出固定 JSON。
- **风险与注意事项**：PDF 排版复杂、图片简历、表格简历容易解析失败；必须保存原文，方便回溯和重新解析。

## 3. AI 职业画像 Agent
- **功能目标**：根据简历生成候选人能力画像，帮助 HR 快速理解候选人，也帮助学生认识自己。
- **输入与输出**
  - **输入**：结构化简历、简历原文。
  - **输出**：技能标签、岗位倾向、优势、短板、成长建议、画像摘要。
- **子技术决策点**
  - 前端：画像卡片、雷达图、标签云。
  - 后端：调用 LLM，保存画像版本。
  - 数据库：需要。
  - 大模型：需要。
  - 向量库：MVP 不需要。
  - 异步：建议需要。
- **方案对比**
  - MVP：Prompt + 固定 JSON Schema，实现快，Agent 感强，但依赖提示词稳定性。
  - 平衡级：规则标签库 + LLM 分析 + 置信度，更稳定、可解释，但需要维护能力标签体系。
  - 高级：能力模型 + 历史面试数据训练，更精准，但数据要求高。
- **最终选择**：MVP 用 LLM 生成职业画像。
- **可落地性说明**：重点做可视化：技能标签、岗位倾向、优势/短板三栏，展示价值明显。
- **风险与注意事项**：不要把 AI 画像包装成绝对结论，应标注“基于简历内容推断”。

## 4. 企业岗位发布与 JD 解析
- **功能目标**：让 HR 发布岗位，并把自然语言 JD 转成岗位画像，供匹配和面试生成使用。
- **输入与输出**
  - **输入**：岗位名称、部门、JD、薪资范围、地点、学历要求。
  - **输出**：职责、硬性要求、核心能力、加分项、岗位标签、岗位画像。
- **子技术决策点**
  - 前端：岗位发布表单、AI 解析预览。
  - 后端：岗位 CRUD、JD 解析接口。
  - 数据库：岗位表、岗位画像表。
  - 大模型：建议需要。
  - 异步：MVP 可同步，平衡级异步。
  - 向量库：MVP 不需要。
- **方案对比**
  - MVP：JD 粘贴 + LLM 结构化解析。
  - 平衡级：岗位模板 + LLM 解析 + HR 确认修改。
  - 高级：企业 ATS 导入 JD。
- **最终选择**：MVP 用 JD 粘贴 + AI 解析。
- **风险与注意事项**：JD 可能存在歧视性或不合规描述，需要后续加入合规提示。

## 5. 人岗匹配 Agent
- **功能目标**：把候选人画像和岗位画像进行匹配，输出分数、理由和风险点。
- **输入与输出**
  - **输入**：候选人画像、岗位画像、简历结构化数据。
  - **输出**：匹配分、匹配理由、缺口、风险点、候选人排序。
- **子技术决策点**
  - 前端：匹配分、排序列表、解释弹窗。
  - 后端：匹配算法、结果持久化。
  - 数据库：匹配结果表。
  - 大模型：建议用于解释，不建议只靠 LLM 打分。
  - 向量库：MVP 不需要，平衡级可选。
  - 异步：建议需要。
- **方案对比**
  - MVP：规则打分 + LLM 生成解释。
  - 平衡级：规则分 + 向量相似度 + LLM 解释。
  - 高级：基于历史招聘结果训练模型。
- **最终选择**：MVP 不建议让 LLM 直接决定分数，而是规则分数为主，LLM 负责解释。
- **风险与注意事项**：AI 评分可能有偏见，必须展示理由和风险点，不要只给一个黑盒分数。

## 6. AI 面试题生成 Agent
- **功能目标**：根据简历、岗位 JD 和人岗匹配结果生成个性化面试题。
- **输入与输出**
  - **输入**：简历结构化数据、岗位画像、匹配缺口。
  - **输出**：简历深挖题、岗位能力题、情景题、追问题、评分要点。
- **子技术决策点**
  - 前端：题目列表、面试流程读取。
  - 后端：题库生成、题目版本保存。
  - 数据库：面试题表。
  - 大模型：需要。
  - 异步：MVP 可同步。
  - 向量库：不必须。
- **方案对比**
  - MVP：LLM 根据上下文一次生成 6-8 题。
  - 平衡级：题型模板 + LLM 填充 + 难度控制。
  - 高级：动态追问 Agent。
- **最终选择**：MVP 生成固定数量题目，并保存。
- **风险与注意事项**：题目不能涉及隐私、歧视性内容；题目需要可复现，不能每次刷新完全不同。

## 7. 虚拟面试流程
- **功能目标**：提供候选人在线面试间，完成设备检测、AI 提问、语音回答、记录内容。
- **输入与输出**
  - **输入**：候选人、面试任务、题目列表、摄像头/麦克风权限。
  - **输出**：面试记录、音频/文本回答、状态流转。
- **子技术决策点**
  - 前端：面试间、设备检测、录音、进度条。
  - 后端：面试会话、题目状态、回答保存。
  - 数据库：面试会话表、回答表。
  - 实时通信：MVP 不必须。
  - 音视频：需要。
  - 异步：ASR 和评价建议异步。
- **方案对比**
  - MVP：前端逐题播放 TTS，MediaRecorder 录音上传。
  - 平衡级：WebSocket/SSE + 实时 ASR + 动态追问。
  - 高级：WebRTC 实时音视频 + 实时 Agent。
- **最终选择**：MVP 做“结构化逐题面试”，不要一开始做开放式实时对话。
- **风险与注意事项**：浏览器权限、录音格式、移动端兼容性会影响演示，需要提前准备备用流程。

## 8. 数字人面试官
- **功能目标**：提升面试沉浸感，让 AI 面试官以头像和语音方式提问。
- **输入与输出**
  - **输入**：面试题文本、面试官形象配置。
  - **输出**：头像动画、语音播报、问题展示。
- **子技术决策点**
  - 前端：虚拟头像、口型/动效。
  - 后端：可不参与，或生成音频。
  - 第三方：HeyGen、D-ID、阿里云数字人可选。
  - TTS：需要。
  - 实时通信：MVP 不需要。
- **方案对比**
  - MVP：静态头像 + Web Speech API + 简单动画。
  - 平衡级：TTS 音频 + 2D Live2D/头像动效。
  - 高级：HeyGen/D-ID/阿里云数字人。
- **最终选择**：MVP 用虚拟头像 + TTS。

## 9. ASR 与 TTS
- **功能目标**：把候选人语音回答转文字，把 AI 面试题转语音。
- **输入与输出**
  - **输入**：音频文件、问题文本。
  - **输出**：转写文本、语音播放结果。
- **子技术决策点**
  - 前端：录音、播放、权限检测。
  - 后端：ASR 调用、音频存储。
  - 第三方：Whisper、阿里云、讯飞。
  - 异步：ASR 建议异步。
  - 文件存储：需要。
  - 实时通信：MVP 不需要。
- **方案对比**
  - MVP：浏览器 Web Speech TTS + 录音上传 + Whisper/云 ASR。
  - 平衡级：云 TTS + 云 ASR + 异步任务队列。
  - 高级：实时流式 ASR/TTS。
- **最终选择**：MVP：浏览器 TTS + 一个稳定 ASR 服务。

## 10. 面试视频录制与回放
- **功能目标**：记录面试过程，供 HR 复核候选人表现。
- **输入与输出**

  - 后端：上传、存储、访问鉴权。
  - 文件存储：需要。
  - 数据库：文件元数据。
  - 异步：视频转码平衡级才需要。
  - 实时通信：不必须。
- **方案对比**

  - 平衡级：前端录制 WebM 上传对象存储。

- **最终选择**：MVP 优先保存音频和文字记录，视频录制作为加分项。

## 11. 反作弊与可信面试检测
- **功能目标**：检测候选人是否离开画面、多人入镜、未开启摄像头或存在明显异常行为。
- **输入与输出**
  - **输入**：摄像头画面、面试时长、检测事件。
  - **输出**：风险事件、可信度提示、异常时间点。
- **子技术决策点**
  - 前端：摄像头检测、人脸检测。
  - 后端：事件记录、风险汇总。
  - AI/CV：face-api.js 或 MediaPipe。
  - 数据库：作弊事件表。
  - 实时通信：不需要。
  - 视频能力：需要摄像头。
- **方案对比**
  - MVP：前端检测摄像头开启、人脸数量、离开画面。
  - 平衡级：MediaPipe 姿态/视线检测 + 事件时间线。
  - 高级：服务端视频分析 + 风控模型。
- **最终选择**：MVP 做基础事件检测，不要做过强结论。

  - 数据库：反馈记录。
  - 大模型：建议需要。
  - 向量库：MVP 不需要。
  - 第三方：学习资源后续可接入。
- **方案对比**
  - MVP：基于评价报告生成反馈建议。
  - 平衡级：能力标签到课程/训练任务映射。
  - 高级：个性化长期成长教练 Agent。
- **最终选择**：MVP：反馈 + 改进建议 + 下次训练方向。

## 16. 数据存储
- **功能目标**：统一保存用户、简历、岗位、面试、音视频、评价报告和匹配结果。
- **输入与输出**
  - **输入**：业务数据、AI 结果、文件元数据。
  - **输出**：可查询、可审计、可回溯的数据记录。
- **子技术决策点**
  - 数据库：PostgreSQL / MySQL / Supabase。
  - 文件存储：本地、Supabase Storage、阿里云 OSS、MinIO。
  - 向量数据库：MVP 先不用。
  - 备份：平衡级需要。
  - 权限：表级和接口级都要控制。
- **方案对比**
  - MVP：Supabase Postgres + Storage。
  - 平衡级：自建 PostgreSQL + OSS/MinIO。
  - 高级：PostgreSQL + 对象存储 + 数仓/日志系统。
- **最终选择**：MVP：Supabase 一体化服务。

## 17. 前后端解耦与 API 设计
- **功能目标**：让前端、后端、Agent 能独立演进，通过 API 清晰协作。
- **输入与输出**
  - **输入**：前端请求、业务参数、文件上传。
  - **输出**：标准 JSON、分页列表、任务状态、错误码。
- **子技术决策点**
  - 前端：统一 API Client。
  - 后端：REST API + OpenAPI 文档。
  - 实时：MVP REST，平衡级 SSE/WebSocket。
  - 鉴权：Bearer Token。
  - 异步：任务 ID 查询状态。
  - 错误处理：统一错误格式。
- **方案对比**
  - MVP：REST + FastAPI OpenAPI。
  - 平衡级：REST + SSE/WebSocket + 任务队列。
  - 高级：API Gateway + 微服务。
- **最终选择**：MVP：REST API。

## 18. Agent 总体架构
- **功能目标**：组织多个 AI 能力模块，让简历解析、画像、匹配、面试题、评价等流程清晰可控。
- **输入与输出**
  - **输入**：简历、JD、面试记录、任务提交。
  - **输出**：结构化解析、画像、匹配结果、题目、报告、反馈。
- **子技术决策点**
  - Agent 形态：推荐工作流式多 Agent。
  - 主控方式：后端 Orchestrator。
  - 框架：MVP 手写工作流，平衡级 LangGraph。
  - 数据库：保存每步输入输出。
  - 异步任务：建议使用。
  - 可解释性：保存模型版本、提示词版本、输入输出。
- **方案对比**
  - MVP：FastAPI 内部函数式 Agent Workflow。
  - 平衡级：LangGraph 工作流编排。
  - 高级：独立 Agent 微服务 + 消息队列。
- **最终选择**：MVP：可控工作流 Agent。

## 19. 部署架构
- **功能目标**：支持本地演示、云端访问、自动更新和基础运维。
- **输入与输出**
  - **输入**：前端代码、后端代码、环境变量、数据库连接。
  - **输出**：可访问 URL、API 服务、数据库、文件访问地址。
- **子技术决策点**
  - 前端：Vercel / Netlify。
  - 后端：阿里云 ECS + Docker / Render / Railway。
  - 数据库：Supabase 或云 PostgreSQL。
  - 文件：Supabase Storage / 阿里云 OSS。
  - CI/CD：GitHub Actions 或平台 Git 部署。
  - 监控：MVP 可简化。
- **方案对比**
  - MVP：前端 Vercel + 后端 ECS/Docker + Supabase。
  - 平衡级：Docker Compose 部署后端/Redis/Postgres + OSS。
  - 高级：Kubernetes + 微服务 CI/CD。
- **最终选择**：MVP：轻量云部署，不上 Kubernetes。

## 20. 安全与隐私
- **功能目标**：保护简历、面试、视频等敏感数据，确保企业只能看自己权限范围内的数据。
- **输入与输出**
  - **输入**：用户请求、角色、企业 ID、资源 ID。
  - **输出**：授权结果、审计日志、脱敏数据。
- **子技术决策点**
  - 鉴权：JWT。
  - 授权：RBAC + 企业租户隔离。
  - 数据保护：文件私有桶、签名 URL。
  - AI 安全：提示词防注入、输出校验。
  - 合规：隐私声明、授权同意。
  - 日志：记录访问和关键操作。
- **方案对比**
  - MVP：JWT + 后端企业 ID 校验 + 私有文件访问。
  - 平衡级：RBAC + Row Level Security + 审计日志 + 加密存储。
  - 高级：合规体系、DLP、权限审批。
- **最终选择**：MVP：后端权限校验 + 私有文件访问。
