# 《JobFit——岗位胜任力评估智能体作品说明》

> 本文面向比赛评审，描述 JobFit 的产品设计、技术路径与当前实现边界。当前代码事实以 [implementation-status.md](./implementation-status.md) 为准。

## 1. 作品简介

JobFit 是面向新一代信息技术岗位的岗位胜任力评估智能体。它不把简历关键词或单一问答分数当作最终结论，而是把简历经历、岗位能力模型和多轮回答组织为可追溯的 Evidence Ledger，形成岗位匹配度、能力边界和可执行的提升建议。

作品聚焦一条可演示、可解释的闭环：

简历上传与解析 → Candidate Competency Profile → Job Competency Profile → 自适应对话面试 → Evidence Ledger → 能力边界识别 → 岗位匹配度 → 自动化评估报告。

## 2. 要解决的问题

- 候选人知道目标岗位名称，却不清楚自己在哪些能力维度已具备证据、哪些仍需补充。
- 通用题库难以根据岗位、项目细节和回答质量持续改变追问。
- 单一分数缺少来源，无法解释结论来自哪段简历或哪次回答。
- 长对话中的经历、矛盾点和未验证信号容易丢失。

JobFit 的回答不是替代招聘判断，而是把岗位能力验证过程变成候选人和评审可以理解、复核的证据链。

## 3. 核心能力

### 3.1 Candidate Competency Profile

系统受控读取 PDF、DOCX 或 TXT 简历，提取技能、项目、经历和教育字段，保存候选人能力标签与简历 Evidence。当前实现是受控文本解析和规则结构化，不将其夸大为自由模型理解。

### 3.2 Job Competency Profile

当前内置 AI 工程师、Java 工程师和产品经理岗位模板。每个模板包含能力项、权重、L0–L5 Rubric、追问策略和 Evidence 要求。用户选择模板后，系统创建可追溯的岗位画像。

### 3.3 固定 Interview Orchestrator

面试 Runtime 按固定状态机工作，不是自由决策型多 Agent：

1. 基于岗位能力模型创建首个问题。
2. 接收候选人的文字回答或浏览器语音转文字结果。
3. 用确定性规则评估回答的相关性、深度、具体性、正确性和证据强度。
4. 选择澄清、要求实例、情景题、难度变化、能力维度切换或结束。
5. 保存消息、评估、Evidence、检索轨迹和记忆。

会话使用客户端请求 ID 与版本号控制重复提交和并发冲突，并在至少八轮回答后允许完成。

### 3.4 Evidence Ledger 与能力边界

每次回答都会形成 Evidence，包含问题、答案、能力维度、信号、强度、支持等级和验证状态。报告根据有效 Evidence、岗位权重和能力等级计算岗位匹配度，而不是由单一模型黑箱给分。

能力边界用 L0–L5 表示：从没有可验证证据，到能够解释、应用、诊断、权衡和优化岗位相关能力。

### 3.5 RAG / BM25 与三层记忆

当前检索层使用 BM25 从内置岗位 Rubric、证据要求和题目策略片段中检索相关内容，并保留 source ID、分数和知识版本。

- Working Memory 保存最近会话消息。
- Summary Memory 每四轮压缩回答摘要，控制长文本上下文。
- Evidence Memory 保存已有 Evidence 的能力等级与强度。

当前没有外部向量数据库、在线题库或真实模型检索服务；内置 BM25 是已实现的确定性检索能力。

### 3.6 自动化评估报告

报告包含：

- 岗位匹配度和评估等级。
- 能力雷达图与分项分数。
- 每项能力的边界、置信度和 Evidence 引用。
- 优势、能力缺口和 P0/P1/P2 提升建议。

前端报告页把这些结果可视化，使评审能够从分数追溯至具体证据。

## 4. 当前实现与诚实边界

| 模块                                         | 当前状态      | 说明                                     |
| -------------------------------------------- | ------------- | ---------------------------------------- |
| 简历解析、候选人/岗位画像                    | implemented   | 已有受控上传、持久化和 JobFit API。      |
| 多轮文字面试、动态追问、Evidence、记忆、报告 | implemented   | 固定确定性 Runtime，并有后端主流程测试。 |
| 浏览器语音转文字                             | frontend_demo | 只形成文本输入，不保存或上传音频。       |
| BM25 检索                                    | implemented   | 使用内置岗位标准片段，不是外部知识库。   |
| 自由 JD 语义建模                             | partial       | JD 文本可保存，能力模型来自模板。        |
| 真实 LLM Provider                            | partial       | 有配置校验，没有真实 Provider 调用证据。 |

因此，作品不声称已经完成真实大模型、在线知识库、视频面试或企业级招聘集成。

## 5. 技术架构

前端使用 React、TanStack Start、TanStack Query、Tailwind 与 Recharts；后端使用 FastAPI、Pydantic、SQLAlchemy、SQLite 与 Alembic。

JobFit 后端围绕简历、画像、评估、面试会话、回答评估、Evidence、记忆、检索轨迹和报告建立持久化模型。认证使用 JWT HttpOnly Cookie，文件处理校验大小、类型、MIME、基本文件签名和可提取文本。

## 6. 创新点

1. **从简历关键词到岗位胜任力模型**：岗位模板将能力、权重、Rubric、追问策略与 Evidence 要求显式化。
2. **从固定题库到自适应追问**：面试 Runtime 按回答强度、覆盖度和难度控制后续问题。
3. **从单一评分到 Evidence Ledger**：匹配度、能力边界和建议均保留可追溯 Evidence。
4. **从长对话遗忘到三层记忆**：工作、摘要和证据记忆共同控制上下文和长期追踪。
5. **从不可复核 AI 结论到确定性评估 Runtime**：当前规则可测试、可解释，并为后续 Provider 扩展保留边界。

## 7. 数据最小化与安全

- 不采集摄像头、视频、录音、音频回放或行为数据。
- 浏览器语音能力只转写为用户确认的文本。
- 简历与评估资源按用户所有权隔离。
- 生产环境拒绝默认 JWT 密钥。
- Evidence 只服务岗位能力评估，不作录用或淘汰强判定。

## 8. 不纳入作品主线

AI 内推网络、企业人才运营、HR 招聘 CRM、ATS、真人面试预约、数字人、虚拟面试官、视频/WebRTC、摄像头监考、录音录像、音视频回放、高级反作弊、行为分析和岗位能力试炼均不属于当前 JobFit 作品范围。

## 9. 后续演进

在保持 Evidence、能力边界和可追溯性不变的前提下，后续可以接入真实 LLM Provider、可维护岗位知识库、任意 JD 的语义建模和浏览器端到端验证。每项能力只有在获得代码、测试和运行证据后，才会从规划升级为当前事实。
